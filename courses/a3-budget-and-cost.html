Learn Data PMO with Phoebe · Leader track · Session 3 of 6

Two pots of money, one honest ledger

Northgate's board approved $3,800k for data in year one - and if it lands in one pot, you will not know you are overrunning until the money is gone. Tonight is the leader's money session: split run from change so overruns cannot hide, cost a data project from its three real ingredients (people, platform, variable), and replace padded line items with one visible 10% buffer plus a monthly variance review. You leave able to read a variance report and spot the project heading over budget months before it actually goes over - which is the only time the information is still useful.

Part 1 · covers run vs change, the two-pot budget

Run money and change money 7 min live

Run money keeps the lights on: platform, licences, managed services - it recurs forever and the question is "is unit cost drifting?" Change money buys new capability: the 10 chartered projects - it ends when the project ends and the question is "are we on plan?" Northgate's split: $1,100k run, $2,700k change. Different questions, different reviews, different pots. Mix them and both questions become unanswerable.

LiveWhy one pot hides the overrun5 min▶

Run spend is lumpy and always growing a little - more users, more data, more licences. That noise is the perfect camouflage for a change overrun:

  • The signal drowns. A $60k project overrun inside a $3,800k mixed pot is a rounding error. The same $60k against a $480k project budget is a 12% alarm bell.
  • The wrong lever gets pulled. Mixed-pot pain triggers "cut cloud spend" memos - while the actual leak is a project burning people-months past plan.
  • Next year's baseline lies. When change spend bleeds into run, year two's "keep the lights on" number quietly inherits year one's overruns - forever.
Real world

The overrun that filed itself under electricity. Northgate month 5: the lakehouse team, behind schedule, quietly leans on extra managed-service hours to catch up. The invoice lands in the run pot - so the lakehouse still reports green on its change budget while run creeps up 8%. Finance flags "platform cost drift" and IT gets the angry email. One tagging rule - every invoice carries a project code or the run code - and the overrun shows up where it belongs, three months earlier, on the project that caused it.

Self-studyWhat each pot's review looks like3 min read▶

The pots get different meetings, because they answer different questions:

  • Run review - quarterly, trend-shaped. Unit costs over time: cost per store served, per dashboard user, per pipeline run. Drift up with no growth to explain it = investigate. This is where FinOps lives (Part 2).
  • Change review - monthly, variance-shaped. Each project against its own charter budget: planned vs earned vs actual (Part 3). Ends when the project ends.

One handoff rule keeps the boundary clean: when a project delivers, its ongoing platform and licence cost moves to run with a named number - agreed at the gate, not discovered on an invoice. A project is not done until its run cost has a home.

Part 2 · covers the three cost families + FinOps basics

What a data project actually costs 8 min live

Every data project's budget is three families. People: FTE months x loaded rate - almost always the big block, and the one leaders underestimate because "the team is already paid for" (they are paid for, and they are finite). Platform: cloud and licences the project consumes. Variable: compute that scales with usage - and for Gen AI work, tokens and inference, the family that can surprise you after launch.

LiveThe three families, and where each one bites5 min▶
  • People - FTE months x loaded rate. Loaded means salary plus overheads, not payslip. The classic leader error is treating internal staff as free: 4 engineers for 6 months is real money whether or not an invoice arrives, and it is capacity no other project can use (a4 does the capacity math).
  • Platform - cloud + licences. Mostly predictable, mostly quotable in advance. The trap is the licence that scales per seat right when self-serve BI succeeds.
  • Variable - compute, GenAI tokens, inference. The only family that can grow AFTER delivery. A pilot that costs pennies at 10 users can cost real money at 4,000 staff - meter it from day one, not after the first surprising invoice.
Real world

The pilot that got popular. Northgate's agentic workflow pilot runs cheap for two months - then store ops discovers it and usage jumps. In the simulator this project lands roughly 20% over on cost, and token spend is the culprit. The team that metered tokens per workflow from week one sees the curve bend in the weekly numbers and adds a cap plus a cheaper model tier. The team that did not meter finds out from Finance, one quarter and one awkward steering meeting later.

Self-studyFinOps in four moves - the leader's version3 min read▶

You do not need a FinOps team on day one. You need four habits, in this order:

  • Tag everything. Every resource carries a project code or the run code. Untagged spend is unmanageable spend - this single rule powers the two-pot split from Part 1.
  • Rightsize. Review what is oversized for its actual load. Dev environments running production-size clusters are the usual first find.
  • Commit discounts. Once run usage is stable and tagged, commit to baseline capacity for the discount - run money only, never speculative change capacity.
  • Watch unit costs. Cost per pipeline run, per dashboard user, per 1k tokens. Totals grow with success; unit costs drifting up is the real warning.

Gen AI adds one instrument: token and inference metering per use case. b9 turns this into the practitioner's cost-control routine.

Self-studyFive questions before you sign a charter budget3 min read▶

The leader's pre-signature checklist, one question per weak spot:

  • "Which family is the biggest, and why?" If the answer is not "people" on a data project, ask what got left out - it usually was.
  • "Is the rate loaded?" Payslip-rate budgets run hot from month one. Loaded means salary plus overheads, agreed with Finance once, reused everywhere.
  • "What is the staffing assumption?" "4 engineers at 70% focus" is a testable claim (a4 tests it). "The team" is not.
  • "What scales after delivery?" Per-seat licences and GenAI tokens grow with success. Name the meter and the ceiling now.
  • "Where does the run cost land?" A number and a pot, agreed at the gate - or the project is not actually costed, only started.
Part 3 · covers the 10% buffer + EVM lite traffic lights

The buffer argument, and reading the dials 7 min live

Every experienced team pads its estimates - the question is whether the padding is visible. Hidden padding in every line item means nobody knows the real cost, and Parkinson's law spends the pad anyway: work expands to fill the money available. The alternative: honest estimates, plus one visible 10% contingency held at portfolio level, released through a monthly variance review with a log of who drew what and why. Same insurance, full visibility - in the simulator this lever alone takes budget variance from +12% to +1%.

LiveEVM lite - three dials an exec can read in a minute5 min▶

Earned value sounds like accounting; for the steering chair it is three numbers. PV - what the plan said we would have done by now. EV - the value of what we actually finished. AC - what we actually spent. Two ratios turn them into traffic lights:

DialFormulaGreenAmberRed - and the question to ask
SPI - scheduleEV / PV0.95+0.85-0.95Below 0.85 · "What re-plan are you proposing?"
CPI - costEV / AC0.95+0.85-0.95Below 0.85 · "What is the EAC and the ask?"
EAC - landing pointBAC / CPINear BACWatchingOver budget + buffer · kill / descope / fund

Below 1.0 means behind or over - and the killer feature is that CPI predicts: divide the total budget (BAC) by today's CPI and you get EAC, the estimate at completion, months before the money runs out. VAC = BAC - EAC is the size of the hole.

Ask for the ratio, not the burn. "We have spent 40% of budget" tells you nothing without knowing what got finished. A project can be 40% spent and 20% done - burn rate alone makes that invisible; CPI makes it a red light.
Self-studyBuffer vs padding - why visible wins3 min read▶

Both approaches reserve roughly the same money. The difference is who can see it and who governs it:

  • Padding hides in each line item. Nobody knows the real estimate, teams spend to their padded number (Parkinson's law), and when a genuine shock hits there is no visible reserve left to draw on - it was all quietly consumed.
  • A buffer is one line everyone can see, owned at portfolio level, drawn down through the monthly variance review with a written reason. Estimates stay honest because teams are not punished for shocks - they are funded from the reserve, on the record.

The drawdown log doubles as a learning tool: after two quarters it tells you WHERE the shocks come from - discovery risk in the data, scope creep from sponsors, or optimistic sizing - and that is next year's estimating fix.

Self-studyThe monthly variance review - a 20-minute agenda3 min read▶

The buffer only works if the review that governs it actually happens. The standing agenda, timeboxed:

  • Minutes 1-5: the dials. SPI and CPI per project, pre-circulated as traffic lights. Green projects get zero airtime - this meeting is for exceptions.
  • Minutes 5-15: amber and red. Each exception owner brings the EAC and ONE ask: buffer draw, descope, or re-baseline. No asks without a number.
  • Minutes 15-18: the drawdown log. Approve or decline each draw, in writing, with the reason. The log is public to the whole data office.
  • Minutes 18-20: buffer health. Reserve remaining vs months remaining. Burning buffer faster than calendar = the portfolio itself is amber - a steering item (a5), not a PMO item.

Twenty minutes, monthly, and no project gets to be surprised at quarter end. The practitioner version, with the full worked numbers, is b9.

Build-along

Read a variance report before it is over ★ 18 min · everyone reads

The month-4 variance report for the lakehouse build lands on your desk. Charter budget (BAC) $480k. The report says: PV $200k, EV $160k, AC $190k. On paper the project is "only slightly over spend" - your job is to see what is actually happening.

Check the burn story first. Spent $190k of $480k - about 40%, month 4 of 10. A burn-rate-only report calls this green. Hold that thought.

Compute SPI. EV / PV = 160 / 200 = 0.80. The team has finished 80 cents of every planned dollar of work. Red on schedule - this project is a month behind and drifting.

Compute CPI. EV / AC = 160 / 190 = 0.84. Every dollar spent bought 84 cents of work. Red on cost too - the "slightly over" story was the burn rate lying.

Project the landing point. EAC = BAC / CPI = 480 / 0.84 = roughly $570k. VAC = 480 - 570 = minus $90k. That hole is bigger than the whole portfolio buffer's share for this project - this is a steering item, now.

Decide like a leader. Options on the table: descope (cut the out-of-scope-adjacent extras), re-baseline honestly with a buffer draw, or kill. NOT an option: silence until month 8. Write the one-line ask you would bring to steering.

★ The whole point of tonight. At month 4 you have choices - descope, re-plan, fund. At month 9 you have a press release. EVM lite exists to move the bad news to the month where it is still cheap.

Homework ◐ 30 min

  • Split YOUR data budget into run and change - even roughly. Note the three items that resisted classification; they are usually where overruns hide today.
  • Pick one live project and compute SPI and CPI from whatever numbers exist. If the numbers do not exist, that finding IS the homework result - bring it.
  • Find your padding: ask one trusted PM what percentage their estimates carry "for safety." Compare it with what a visible 10% portfolio buffer would cost instead.
Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · Why does Northgate keep run ($1,100k) and change ($2,700k) in separate pots?

Two pots, two questions, two reviews. Run gets a quarterly unit-cost trend review; change gets a monthly variance review per project. Merge them and a $60k project overrun becomes invisible noise inside $3,800k.

2 · A project reports CPI = 0.84. What does that mean?

CPI = EV / AC. Below 1.0 = over cost. It is a ratio of value earned to money spent, not a burn percentage - and dividing BAC by it forecasts the landing point months early. Schedule is SPI's job.

3 · What makes a 10% portfolio buffer better than padding every line item?

The money reserved is roughly the same either way. Padding disappears into the lines and gets spent (work expands to fill the money available); a visible buffer is governed, logged, and teaches you where the shocks actually come from.
